# AI Policy: Immich

- **Project**: Immich
- **Ecosystem / Category**: Self-Hosted Media Platform / TypeScript, Dart & Python
- **Source URL**: https://github.com/immich-app/immich/blob/main/CONTRIBUTING.md
- **Reference Document**: Immich Contributing Guidelines (`CONTRIBUTING.md`)
- **Primary Stance**: Forbidden

## Verbatim Policy Text

> "Contributors are explicitly asked NOT to open pull requests generated with an LLM. LLM-generated code often requires an inefficient amount of back-and-forth review because even single-line changes can have a significant impact, and we cannot reliably verify that the contributor understands all implications.
>
> Using LLMs to solve or fix issues labeled as 'good first issue' is forbidden, and PRs doing so are subject to automated closure."

## 4-Dimension Breakdown

### 1. Usage Regulations
- **Overall Level**: `forbidden`
- **Scope**: Source code pull requests generated by LLMs.
- **Exceptions**: None for code submissions; personal research only without generating PR diffs.

### 2. Disclosure Requirements
- **Mandatory Disclosure**: N/A (LLM code generation is forbidden).
- **Enforcement**: Suspected LLM PRs are closed.

### 3. Comprehension & Accountability
- **Human Comprehension**: Required. Prohibition is explicitly justified by the fact that maintainers cannot verify contributor understanding, leading to maintainer exhaustion.
- **Legal Accountability**: AGPL-3.0 compliance.

### 4. Review & Issue Rules
- **Beginner Issue Protection**: Strictly forbidden to use LLMs on issues labeled "good first issue".
- **Automated PRs / Issues**: Automated or LLM-generated PRs are subject to automated closure.
