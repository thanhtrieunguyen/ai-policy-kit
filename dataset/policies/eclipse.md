# AI Policy: Eclipse Foundation

- **Project**: Eclipse Foundation
- **Ecosystem / Category**: Open-Source Foundation / Enterprise Tooling, IDE & Java
- **Source URL**: https://www.eclipse.org/org/documents/
- **Reference Document**: Generative Artificial Intelligence Usage Guidelines for Eclipse Committers
- **Primary Stance**: Restricted

## Verbatim Policy Text

> "A committer's responsibilities remain identical whether code or content is written by a human or generated by AI. Committers bear full responsibility for verifying that all contributions are technically correct, fully understood, and maintainable.
>
> Code or content cannot be attributed to an AI tool. A human must take legal and technical responsibility.
>
> If a developer cannot understand a piece of AI-generated code, they are expected not to push it.
>
> Contributions exceeding standard thresholds (e.g. >1,000 lines) must still be tracked and coordinated via the Eclipse IP Team."

## 4-Dimension Breakdown

### 1. Usage Regulations
- **Overall Level**: `restricted`
- **Scope**: Source code, plugins, documentation, specifications.
- **Exceptions**: Permitted with IP Team oversight; non-understandable code must not be pushed.

### 2. Disclosure Requirements
- **Mandatory Disclosure**: Required for substantial contributions (>1,000 lines) through Eclipse IP Team tracking.
- **Attribution Rule**: Code cannot be attributed to an AI tool; commit metadata must identify the human author.

### 3. Comprehension & Accountability
- **Human Comprehension**: Required. Committers must verify that all contributions are understood, maintainable, and clean.
- **Legal Accountability**: Eclipse Public License (EPL-2.0) and Eclipse IP Due Diligence Process.

### 4. Review & Issue Rules
- **Automated PRs / Issues**: Autonomous PRs without committer sponsorship are not merged.
- **Automated Reviews**: Not recognized as meeting Eclipse Committer review standards.
